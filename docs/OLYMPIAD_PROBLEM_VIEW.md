# Перегляд задач олімпіади

Картка на `/olympiads` відкриває `/olympiads/{olympiadId}`. Сторінка показує назву олімпіади та видимі задачі зі складністю і балами. Картка задачі відкриває `/olympiads/{olympiadId}/problems/{problemId}` з умовою, форматами введення й виведення та прикладами. Обидві сторінки підтримують прямі посилання й перезавантаження. [SCRUM-8](https://coderank.atlassian.net/browse/SCRUM-8)

## Контракт API

| Метод і маршрут | Успішна відповідь | Коли повертається `404` |
| --- | --- | --- |
| `GET /api/v1/olympiads/{olympiadId}/problems` | `200` і масив об’єктів з `id`, `title`, `difficulty`, `maxPoints`. Порядок задає `OlympiadProblems.Position`. Якщо видимих задач немає, API повертає `[]`. | ID неправильний, олімпіади немає або вона не опублікована. |
| `GET /api/v1/olympiads/{olympiadId}/problems/{problemId}` | `200`, поля зі списку та `statement`, `inputFormat`, `outputFormat`, `examples`. Приклад містить `inputData`, `expectedOutput`, `explanation`. Приклади впорядковано за `ProblemExamples.Position`. | Олімпіада недоступна, ID задачі неправильний, задача відсутня, не належить олімпіаді або її зв’язок приховано. |

Обидва GET публічні. Доступ визначають `Olympiads.IsPublished` та `OlympiadProblems.IsVisible` саме для запитаної олімпіади. Бали беруться зі зв’язку задачі з олімпіадою. `difficulty`, `inputFormat`, `outputFormat` і `explanation` можуть бути `null`. За відсутності прикладів `examples` дорівнює `[]`. Власний CRUD працює окремо через захищені маршрути `/api/v1/problems`.

Сторінки показують завантаження, порожній список, недоступність і мережеву помилку з повтором запиту. Текст із БД вставляється через `textContent`. Приклади зберігають пробіли та перенесення рядків.

## Ручна перевірка

1. Використай окрему тестову БД із чинною схемою. Підготуй опубліковану олімпіаду з двома видимими задачами, у яких порядок `Position` відрізняється від порядку ID, і однією прихованою задачею. До першої задачі додай два приклади з різними позиціями. Також підготуй опубліковану олімпіаду без видимих задач і неопубліковану олімпіаду зі зв’язаною задачею. Обліковому запису API потрібен `SELECT` на `dbo.Olympiads`, `dbo.OlympiadProblems`, `dbo.Problems` та `dbo.ProblemExamples`.
2. Запусти `dotnet run --project backend/CodeRank.Api --launch-profile https` із локальними секретами для тестової БД. Запусти Vite з каталогу `frontend` командою `npm run dev` після `npm ci`. Відкрий `http://localhost:5173/olympiads` без входу. Переконайся, що натискання картки відкриває потрібний список. [Локальне наповнення БД](DATABASE_SEEDING.md)
3. Звір назви, бали, складність і порядок видимих задач. Відкрий першу задачу, звір умову, обидва формати й порядок прикладів. Онови URL і повернися назад. На вузькому екрані довгий текст і приклади мають поміщатися без горизонтального прокручування сторінки.
4. Відкрий опубліковану олімпіаду без видимих задач. API має повернути `200 []`, сторінка — повідомлення «Поки немає доступних задач». Запроси список неопублікованої олімпіади та деталі прихованої задачі. Очікуй `404` без даних задачі. Повтори з відсутніми ID та з ID задачі з іншої олімпіади.
5. Під час переходу зі списку олімпіад на її сторінку вимкни мережу в DevTools. Після повідомлення про помилку віднови мережу й натисни «Спробувати ще раз». Список має завантажитися. Повтори на сторінці умови. Для перевірки XSS додай у текст тестової задачі рядок на кшталт `<img src=x onerror=alert(1)>` і переконайся, що він відображається як текст.
6. Перевір звичайний вхід і маршрут `/problems` з тестовим акаунтом. Публічна сторінка олімпіади має відкриватися без JWT. Прямий запит до `/api/v1/problems/{id}` без JWT має повертати `401`.
